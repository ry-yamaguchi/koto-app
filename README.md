# Koto

**AIと一緒にアプリ・Webサイトを作り、さくらインターネットのサービスでそのまま公開できる macOS 向けデスクトップIDE。**

> 本アプリ「Koto」は個人が開発・提供する非公式ツールであり、さくらインターネット株式会社の製品ではありません。さくらインターネットの各サービス（AI Engine・AppRun・レンタルサーバ 等）に接続・公開する機能を持ちますが、同社が提供・保証するものではありません。

プログラミングが初めての方でも、AIに日本語で頼むだけでコードの作成・修正・実行ができ、完成したものを「さくらのレンタルサーバ」「さくらのAppRun」、さくらのクラウド基盤上の国産PaaS「HANAMII」へワンクリックで公開できることを目指したアプリケーションです。AIエンジンには [さくらのAI Engine](https://ai.sakura.ad.jp/) を利用します。

## 特徴

- **日本語でAIに頼むだけ** — コードの作成・修正・説明・デバッグをAIが代行します。
- **AIが自分で作業する（エージェント）** — ファイルの読み書き、コマンド実行、プレビュー表示までAIが実行。人間に操作を要求しません（AIが自分で手を動かす体験）。
- **Claudeを頭脳として併用可能** — 自分のAnthropic APIキーを登録すると、Claudeを司令塔にした「Claude頭脳モード」に切り替えられます（さくらのAI Engineとの併用も可）。
- **権限モードで安全に** — 「おまかせ」と「毎回確認」を切り替え可能。危険なコマンドは常に確認します。
- **ワンクリック公開** — さくらのレンタルサーバ（rsync）／AppRun（コンテナ）／HANAMII（ZIPアップロード・環境変数対応）／Vercel（海外PaaS）に対応。
- **公開先に最適化** — 選んだ公開先に合わせて、AIが「その環境で動く形」を提案します。
- **資料をAIの根拠に（RAG）** — 手元のファイルやWebページを「資料」として登録すると、AIが資料を根拠に出典付きで回答します。
- **画像も理解** — スクリーンショットを渡すと、読み取り→実コードの修正まで自動でつながります。
- **Web検索内蔵** — 最新情報の検索とWebページの読み取りに対応。
- **APIキーはOSのキーチェーンで暗号化** — 平文では保存しません。

## 画面の構成

Koto には2つのモードがあります。画面上部で切り替えます。

| モード | 用途 | 構成 |
|---|---|---|
| **IDEモード** | 実際にアプリ/サイトを作る | ファイルツリー・エディタ・ターミナル・AIチャット・ワークフローバー |
| **チャットモード** | 相談・調査・質問 | 全画面のAIチャット（セッション履歴付き）。開発作業はIDEモードへ誘導 |

## 機能詳細

### ① AIアシスタント

さくらのAI Engine（OpenAI互換API）を利用したAIアシスタントを搭載しています。自分のAnthropic APIキーを登録すれば、Claudeを頭脳として使う「[② Claude頭脳モード](#-claude頭脳モード)」に切り替えることもできます。

- **モデルの自動追従** — 利用可能なモデル一覧を起動時・キー登録時に自動取得します。提供モデルが増減しても追従し、選択中モデルが廃止された場合は自動でフォールバックして通知します。
- **モデルの自動割り振り** — ツールを使えないモデルがファイル操作を求められた場合、その作業だけツール対応モデルへ切り替えて実行します（切替は明示されます）。ツール対応の判定はモデル名で決め打ちせず、実際に使ってみた結果（構造化ツール呼び出しが返ったか／エラーになったか）を記憶して次回以降に活かします。未確認のモデルはまずツール付きで試し、新しいモデルが増えても自動で判定します（記憶は30日で失効し再確認します）。
- **コンテキスト管理** — 現在のプロジェクト（名前・種別・公開先・ファイル構成）をAIに渡します。送信履歴は直近のやり取りに制限し、トークン消費を抑えます。
- **モード別の振る舞い** — IDEモードでは開発作業を主導し、チャットモードでは相談役に徹します（存在しないUIを案内しないよう文脈を分離）。
- **日本語限定の応答** — 他言語の混入を抑えるようサンプリングとプロンプトを調整しています。

**モデルごとの対応状況**

| モデル | ツール（ファイル操作） | 画像 | 備考 |
|---|---|---|---|
| Qwen3-Coder 480B（`Qwen3-Coder-480B-A35B-Instruct-FP8`） | ○ | × | **既定・推奨**（IDEモード） |
| Qwen3-Coder 30B（`Qwen3-Coder-30B-A3B-Instruct`） | ○ | × | チャットモード既定 |
| GPT-OSS 120B（`gpt-oss-120b`） | ○ | × | 推論型 |
| Kimi K2.6（`preview/Kimi-K2.6`） | ○ | ○ | 推論型。指示追従はQwen3-Coderより弱め |
| Qwen3-VL 30B（`preview/Qwen3-VL-30B-A3B-Instruct`） | × | ○ | 画像読み取り用 |
| Phi-4 multimodal（`preview/Phi-4-multimodal-instruct`） | × | ○ | 画像読み取り用 |
| llm-jp 3.1 8x13b（`llm-jp-3.1-8x13b-instruct4`） | × | × | サーバー側がツール非対応 |

### ② Claude頭脳モード

さくらのAI Engineに加えて、自分の Anthropic APIキーを登録すると **Claude** を"頭脳"として使えます。claude.ai のサブスクリプションでのログインは提供しておらず、**自分のAPIキーを登録するBYO方式のみ**に対応しています。

- **3つのモード** — キーの登録状況に応じて自動的に決まります。

  | モード | 条件 | 動き方 |
  |---|---|---|
  | 完全体 | Claude・さくらのAI Engine 両方のキーを登録 | Claudeが司令塔となり、まとまった実装作業は `delegate_implementation` ツールでさくらのAI Engine（既定 `Qwen3-Coder-480B-A35B-Instruct-FP8`）へ委譲します。AI Engineの出力は直接ファイルへ書き込まれ、Claudeには「書き込んだファイル一覧・バイト数・トークン数」の要約だけが返ります（Claudeの高コストな出力トークンを節約する設計）。 |
  | Claudeのみ | Claudeキーのみ登録 | Claudeが読み書き・コマンド実行まですべて自分で行います。 |
  | さくらのAI Engineのみ | AI Engineキーのみ登録、またはモードOFF | 従来どおり「① AIアシスタント」の経路で動きます。 |

- **切り替え方** — 画面右下のステータス表示（IDEモード・チャットモードの両方にあります）をクリックすると、Claudeとさくらの AI Engineをその場で切り替えられます。両方のキーが登録済みのときだけ切り替え可能です。設定画面（⌘ ,）の「チャットの頭脳」からも変更できます。
- **使えなくなったときの案内** — Claudeが料金不足などで使えなくなると、さくらのAI Engineのキーがあれば「さくらのAI Engineに切り替えて続けますか？」と提案が表示されます。自動では切り替わらず、ボタンを押したときだけ切り替えて同じ内容を送り直します。
- **Claudeが使えるツール** — ファイルの読み書き（Read/Edit/Write）・検索（Glob/Grep）・コマンド実行（Bash）に加えて、IDE固有の `fetch_url`（URL取得）・`search_docs`（「📚 資料」の検索）・`open_preview`（プレビュー表示）を使います。完全体モードではさらに `delegate_implementation`（さくらのAI Engineへの実装委譲）が加わります。
- **モデル選択** — 起動時に、お使いのAPIキーで**実際に提供されているモデルを自動で取得**して一覧にします（新しいモデルが出たらKotoを更新しなくても選べます）。キーが未登録・オフライン等で取得できないときは、代表的なモデル（Fable 5 / Opus 5 / Sonnet 5 / Haiku 4.5）を表示します。
- **画像** — Claudeモードでは、Claude自身が画像を直接読み取ります（「⑤ 画像入力」にあるAI Engine側の2段階処理は経由しません）。
- **会話の継続** — Claudeとのやり取りは保存され、アプリを再起動しても会話の続きから再開できます。
- **料金** — 自分のAnthropic APIキーによる従量課金で、**さくらのAI Engineとは別枠**です。初回利用時に同意ダイアログを表示し、月ごとの利用額表示と警告しきい値の設定にも対応しています。

### ③ AIが使えるツール（エージェント機能）

AIは Function Calling により、自分で以下のツールを呼び出して作業を進めます（最大数ラウンドの自律ループ）。

| ツール | できること |
|---|---|
| `read_file` | プロジェクト内のファイルを読む（修正前に必ず全文を読む） |
| `write_file` | ファイルを新規作成・全面書き換え保存（**上書き前に自動バックアップ**を `.sakuraide-backup/` に保存） |
| `edit_file` | 既存ファイルの一部だけを置換して部分修正（全文を書き直さない分、速く・失敗しにくい。上書き前の自動バックアップは write_file と同じ） |
| `list_files` | プロジェクトのファイル構成を確認する |
| `search_in_files` | プロジェクト内のファイルを横断して文字列を検索し、該当ファイル・行番号を得る |
| `run_command` | ビルド・構文チェック・テスト等のコマンドを実行（60秒制限・出力上限あり） |
| `open_preview` | ブラウザでプレビューを開く |
| `fetch_url` | 指定URLのページ本文を取得して読む |
| `search_web` | Web検索（Tavily / Brave、登録時のみ） |
| `search_docs` | 登録済みの「📚 資料」を検索して抜粋を得る（資料機能が有効なプロジェクトのみ） |

> AIは「ファイルを保存しました」「コマンドを実行しました」のように作業結果を一言で報告し、コード全文はチャットに貼りません。ユーザーに残る操作は「② 試す での確認」「③ 公開」「実際の情報（文章・画像）の提供」だけになるよう設計されています。

### ④ 権限モード（おまかせ／毎回確認）

AIによるファイル変更・コマンド実行をどこまで自動で許可するかを切り替えられます。

- **🪄 おまかせ** — 確認なしでAIが作業を進めます（スピード重視）。
- **✋ 毎回確認** — ファイル変更・コマンド実行のたびに承認を求めます（安心重視）。
- **危険なコマンドは常に確認** — `rm` / `sudo` / `mkfs` / `dd` / `kill` / `chmod 777` / リダイレクトでのデバイス書き込み / `git push`・`reset --hard` などは、モードに関わらず必ず確認します。

### ⑤ 画像入力（ビジョン・2段階処理）

- スクリーンショットや参考画像をチャットに添付して、AIに見せながら相談できます。
- IDEモードでは**2段階処理**を行います: 画像対応モデルが「読み取りだけ」を担当し、その結果を本来のツール対応モデルへ引き継いで、実コードを確認した上で修正まで実行します（「🖼 画像を◯◯で読み取り、◯◯で実行します」と明示）。画像を渡しただけで実際のファイル修正まで到達します。
- 画像は送信前に自動で適切なサイズに縮小されます。

### ⑥ Web検索・URL参照

- メッセージにURLを含めると、IDEがそのページ本文を自動取得してAIに渡します。
- 検索が必要そうな質問では、IDEが自動でWeb検索を行い結果をAIに渡します（ツール非対応モデルでも機能します）。
- 検索プロバイダは **Tavily** と **Brave** に対応し、両方を登録して**優先順位**を指定できます（未登録側は自動でもう一方を使用）。
- 検索キー未登録時は、AIは推測せずユーザーにURLの提供を依頼します。

### ⑦ 資料（AIに読ませる資料）

さくらのAI Engine の RAG API を利用した「📚 資料」機能で、AIに事前に資料を読ませておけます。タイトルバーの「📚」から開きます。

- **資料の登録・管理** — txt / pdf / html / docx / xlsx / md を登録でき、取り込み状況（🕐 取り込み中 → ✅ 利用可能）を自動で追跡。名前・タグの編集、削除（確認付き）、登録した資料への「試し質問」ができます。
- **チャットの根拠に** — プロジェクトごとに「このプロジェクトのチャットで資料を使う」を有効にすると、送信内容に関連する資料があるときだけIDEが自動で抜粋を添付し、AIが**出典（資料名）付き**で回答します（どのモデルでも機能）。ツール対応モデルは `search_docs` で能動的に検索もできます。タグで対象資料を絞り込めます。
- **Webから資料を作る** — Web検索（「さくらのナレッジから探す」絞り込み付き）→ チェックしたページだけ取得 → 内容確認 → アップロード、までを一続きで実行。資料には出典URLと取得日時が記録され、ローカルの控えフォルダにも保存されます。
- **さくらの資料パック** — レンタルサーバ／AppRun／AI Engine／HANAMII の公式ドキュメントをまとめた既定のURLセットを、「取り込む」ボタン一つで資料に一括登録できます。
- **安全設計** — 資料の追加・削除は必ずユーザーのパネル操作で行い、AIには読み取り専用の検索ツールしか渡しません。アップロードした資料はさくらのクラウド（AI Engine）に保存される旨をUIに明示しています。
- **費用の仕組み** — 資料の全文がAIに送られることはありません。会話時は関連する抜粋（最大3件×2,000字）だけが渡り、既定モデルで1メッセージあたり最大0.1〜0.2円程度です。取り込み時の索引化は一回だけ行われます。

### ⑧ プロジェクト作成

「新規プロジェクト（AI）」から、作りたいものを日本語で伝えるだけで土台を作ります。

- **種別** — 🌐 Webサイト（LP／お店のサイト／ポートフォリオ／ブログ風）か、⚙️ アプリかを選択。
- **公開先** — あとで決める（おすすめ）／レンタルサーバ／AppRun などを選択。公開先に応じた専用構成でファイルが作られます。
- **このあとチャットで作業するAI** — さくらのAI Engine と Claude のうち、APIキーを登録済みのものだけが選べます（両方登録済みならどちらか選択、片方のみなら自動でそちらに固定）。使用モデルも選べます。選択内容はチャットの頭脳・モデル設定に反映され、次回のデフォルトとしても記憶されます。
- **モーダルでは待ちません** — 「作成」を押すとすぐにプロジェクトが開き、実際のファイル作成はIDEのチャットに依頼されます。作業の様子はチャット欄でそのまま見えるので、途中で「やり直して」「続けて」と日本語で言い直せます（以前のように一度の応答に全部詰め込む必要がないため、出力が長くて途中で切れる、といった失敗も起きにくくなりました）。
- 既存のフォルダを開いて作業することもできます。
- APIキーが1つも登録されていない場合は、最小限のローカル雛形と案内ファイルだけを作成します（AIへの依頼は行いません）。
- 生成内容は `.sakuraide.json`（隠しメタファイル）に記録され、AIへの文脈付与に使われます。

### ⑨ ワークフロー（作る→試す→公開）

画面上部のワークフローバーが「**① 作る → ② 試す → ③ 公開**」の流れを案内します。

- **① 作る** — AIチャットに作りたい内容を伝えます。
- **② 試す** — 実行方法を自動判定して動かします（`index.html` はブラウザ、PHPは `php -S`、Nodeは `node`/`npm start`）。起動したサーバは「⏹ サーバー停止」で止められます。
- **③ 公開** — 公開モーダルを開きます。
- **公開先の変更** — 作成後でもワークフローバーから公開先を変更できます。変更するとAIに渡す前提も切り替わり、「今のコードがこの環境で動くか確認できます」とチャットに案内します。

### ⑩ 公開先プロファイル

選択中の公開先ごとに「その環境でうまくいく構成」の知識をIDEが保持し、AIのコンテキストに注入します。これにより、環境に合わない作り（例：AppRunでローカルファイルに永続保存する）をAIが事前に避けます。

| 公開先 | 主な前提 |
|---|---|
| さくらのレンタルサーバ | 静的HTML/CSS/JS + PHP + MySQL。常駐サーバ（Node.jsのlisten）は不可。 |
| さくらのAppRun | Dockerコンテナ。ステートレス前提。ポートは環境変数で受け取り、永続データは外部ストレージへ。 |
| HANAMII | さくらのクラウド基盤上の国産PaaS。ZIPアップロードでNode等の常駐アプリも公開可。データは国内。 |
| Vercel | 静的サイト／フロントエンド向けの海外PaaS。ポートをlistenする常駐サーバは不可（サーバーレス化が必要）。データは国外。 |
| さくらのVPS | 自由度が高く常駐プロセスも可。ただし構築・運用は自分で行う（IDEからの公開は設計済み・実装予定）。 |
| さくらのクラウド | 最も自由なIaaS。上級者向け。 |
| その他 / ローカル | 特定環境に依存しすぎない一般的な構成。 |

### ⑪ 公開（デプロイ）

公開モーダルから公開できます。公開先は「さくらインターネットのサービス」と「さくら以外」にグループ分けして表示されます。

- **さくらのレンタルサーバ** — `rsync` でファイルをアップロード。HTML/PHPサイト向け。
- **さくらのAppRun** — 内蔵ビルダー（または docker）でビルドしてコンテナとして公開。再公開はPATCH更新で公開URLを維持し、**IPアクセス制限**（限定公開）にも対応。
  - **💰 費用にご注意ください。** イメージの置き場として**コンテナレジストリ**を1つ使います。これは**月額220円（税込・ストレージ5GiBまで）**の固定料金で、**AppRunのアプリを消しただけでは止まりません**。公開URLの下に費用を常時表示し、「🗑 破棄する」でレジストリごと削除できます（削除するかはその場で選べます）。
  - **🔗 破棄すると公開URLが変わります。** URLはアプリごとに決まるため、破棄して公開し直すと別のURLになり、元には戻せません。
- **HANAMII** — プロジェクトをIDEがZIP化してアップロード → ワークスペース選択 → 公開URL表示 → 再公開／破棄まで。**環境変数**の設定（シークレット対応・コードからのキー名自動検出チップ付き）に対応。静的サイトは最小サーバ一式を自動同梱してそのまま公開できます（利用者のファイルは変更しません）。
- **Vercel** — プロジェクトのファイルをIDEが直接アップロード → デプロイ作成 → 公開完了までポーリングして公開URLを表示。海外PaaSのため常駐サーバは不可・データは国外に置かれます。
- **🔰 初めて公開する方へ** — 各公開先のフォームに、契約・SSH有効化などの準備手順と「つまずいたら」FAQを折りたたみで用意しています。
- **公開後の確認動線** — 完了後に「🌐 公開したサイトを開く」ボタン等でサイトを確認でき、公開状態はステータスバーに「🌐 公開済み（公開先 M/D）」として表示されます。
- **📡 公開したもの一覧**（メニュー「表示」→「公開したもの一覧…」）— **全プロジェクトを横断して**、どの公開先に何を公開したかを一覧できます。公開先ごとにまとまり、公開日時の新しい順に並びます。各行から公開URLを開く／コピーする、そのプロジェクトを開く、**🗑 破棄する**ができます。
  - **🗑 破棄**は、さくらのAppRun と HANAMII に出ます（Koto から止められる公開先）。Vercel とさくらのレンタルサーバは Koto から削除できないため、どこで消せばよいかを案内します。
  - **プロジェクトを削除するときも、公開を一緒に破棄できます。** フォルダをゴミ箱へ移すと「どこに何を公開したか」の記録も一緒に消え、後から Koto では止められなくなるため、削除の確認画面で先に破棄できるようにしています（既定でオン。破棄に失敗したときはフォルダを削除しません）。
  - この一覧は **Koto がローカルに持つ公開の記録**（各プロジェクトの `.sakuraide.json`）です。APIキーもネットワークも使わないため、**公開先のサービスに障害が出ているときでも開けます**（「あのサービスに何を公開していたか」をすぐ確認できる、というのがこの機能の目的です）。
  - 一方、**いま実際に公開中かどうかの正解はサービス側にしかありません**（サービス側で削除しても記録は残ります）。画面にその旨を明示し、各サービスの管理画面へのリンクを併記しています。別のPCや管理画面から公開したものは記録が無いため表示されません。

### ⑫ 公開前セキュリティチェック

公開の直前に、AIがコードを確認して秘密情報の混入や危険な記述がないかをチェックします。

- 秘密情報を含みそうなファイル（`.env` / 認証情報など）を検出します。**これらの中身はAIへ送りません**（ファイル名だけを伝えます）。
- 判定が「要確認」の場合は、公開前に内容を確認する画面を表示します（理解した上で公開も可能）。判定に迷いがある場合は「要確認」側に倒します。
- キー未登録・予算超過・失敗時はチェックをスキップし、**公開自体はブロックしません**。

### ⑬ 公開物に含めないもの

どの公開先でも、次のものは**必ず除外**します（定義は [`src/shared/publishExclude.ts`](src/shared/publishExclude.ts) の1箇所だけにあり、テストで固定しています）。

| 種類 | 対象 |
|---|---|
| Koto の内部フォルダ | `.sakuraide`（チャット履歴）/ `.sakuraide-backup`（🕘 履歴）/ `.sakura-cloud`（クラウドの状態）/ `.sakuraide.json` |
| **秘密が入るファイル** | `.env`・`.env.*` / SSH秘密鍵（`id_rsa` 等。`.pub` は対象外）/ `*.pem`・`*.p12`・`*.pfx` / `.netrc`・`.pgpass` |
| 重い・環境依存 | `.git` / `node_modules` |
| OS の雑音 | `.DS_Store` |

**環境変数（APIキー等）は `.env` を置くのではなく、公開先の設定画面から登録してください。** さくらのAppRun・HANAMII・Vercel はいずれも環境変数の設定に対応しています（HANAMII はコードからキー名を自動検出して候補を出します）。

### ⑬ エディタ・ファイル管理・ターミナル

- **エディタ** — Monaco エディタ。タブ表示、未保存マーク（`•`）、未保存タブを閉じる際の確認。
- **ファイルツリー** — プロジェクト切り替え、リアルタイム更新、右クリックで「名前の変更」「削除（ゴミ箱へ）」「新規ファイル」。Finderからのドラッグ＆ドロップ取り込みに対応（画像は `images/` へ自動整理）。
- **ターミナル** — xterm ベース。プロジェクトの作業フォルダに自動で `cd`。IDEからのコマンド（公開・サーバ起動など）もここに流れて進行が見えます。
- **🕘 履歴（前の状態に戻す）** — AIの変更・自分の編集の直前に自動で取られたスナップショット（直近50件）の一覧から、**選んだ時点の状態にまるごと戻せます**（それより後の変更はすべて取り消されます）。一覧にはそのときの指示文が並ぶので、「3つ前のデザイン」を内容で選べます。戻す直前の状態も履歴に残るため、戻しすぎてもやり直せます。画面上部の「🕘 履歴（前の状態に戻す）」またはファイルツリーの 🕘 から開きます。
- **チャット履歴の保存** — チャットのやり取りはプロジェクト内 `.sakuraide/chat.json` に保存され、アプリを再起動しても続きから見られます。
- **GitHubへの保存** — Personal Access Token を登録すると、プロジェクトを新規リポジトリとして作成してそのまま保存できます。

### ⑭ 認証情報・利用上限の管理

- **認証情報の一元管理（⌘ ,）** — さくらのAI Engine（複数キー・「使用中」切替）／さくらのクラウド／HANAMIIトークン／Vercelトークン／コンテナレジストリ／Web検索（Tavily・Brave）を統一カードで管理し、🔌 接続テストが可能。すべてOSキーチェーンで暗号化されます。
- **利用上限（予算）** — キーごと・モデルごとに月間の利用額上限を設定でき、超過時はリクエストを停止。設定画面で利用量と料金の目安（トークン＝文字数の目安）を確認できます。
- **オンボーディング** — 初回起動時に、APIキー取得・登録・接続テストを案内するウィザードを表示します。
- **ヘルプ** — メニューバーの「ヘルプ → 使い方ガイド」から、IDE内で使い方ガイドを開けます。

### ⑮ セキュリティ設計

- **APIキーの暗号化** — OSのキーチェーン（`safeStorage`）で暗号化して保存。平文では保存しません。シークレット値（HANAMII環境変数のシークレット等）はディスクに保存せず、送信時のみ利用します。
- **キーの取り回し** — 各APIキーは使う瞬間にだけ復号してメインプロセスへ引数で渡し、メインプロセス側では保持しません。
- **レンダラのサンドボックス化** — `contextIsolation` / `sandbox` / `webSecurity` 有効。外部リンクは既定ブラウザで開き、アプリ内遷移を禁止。
- **ファイル操作の制限** — `read_file` / `write_file` / `edit_file` / `search_in_files` はプロジェクトフォルダ内に限定（絶対パス・`..` を禁止）。上書き時は自動バックアップ。
- **危険コマンドの常時確認** — 権限モードに関わらず確認を要求。
- **外部テキストへの耐性** — Webページや資料の抜粋に含まれる指示文には従わないようAIに指示しています。

npm install

npm run start

## 既知の制約

- **Apple Silicon 専用** — 配布しているのは arm64 版のみです。Intel Mac には対応していません。
- **APIキーの再登録が要る場合があります** — APIキーは macOS のキーチェーンに保存され、その読み出し許可は**アプリの署名**に紐づきます。**同じ証明書で署名した版どうしの更新では、APIキーはそのまま使えます**（v0.3.2 → v0.3.3 の自動更新で確認済み）。署名の実体が変わる更新（証明書の変更など）では、確認ダイアログが出るか再登録が必要になります（v0.3.0 で署名を導入したときは1回出ました）。該当する場合は CHANGELOG に明記します。
- **公開先** — 現状の公開はレンタルサーバ／AppRun／HANAMII／Vercelに対応。VPS（設計済み）／さくらのクラウドは今後のバージョンで対応予定です。
- **AI Engineの画像生成** — 現在さくらのAI Engineには画像生成モデルがないため、画像は「ユーザーが用意」または「CSS等での表現」で対応します。
