Koto 使い方ガイド

AIと一緒にアプリやWebサイトを作り、さくらインターネットで公開しましょう。

Koto は個人開発の非公式ツールです（さくらインターネットの製品ではありません）。

Kotoとは

Kotoは、プログラミングが初めての方でもアプリやWebサイトを作れる開発ツールです。AIに日本語で頼むだけで、コードの作成・修正・実行をお手伝いします。完成したものは、さくらインターネットのサービスでそのまま公開できます。

はじめの設定（APIキーの登録）

最初に、さくらのAI EngineのAPIキーを登録します。これがAIと会話するための鍵になります。

  • さくらのAI Engine でAPIキーを発行します。
  • Kotoの設定画面（AIチャット付近の設定ボタン）に、発行したAPIキーを貼り付けて保存します。
APIキーはお使いのパソコン内に安全に保存され、AIへの問い合わせにのみ使われます。

Claudeを"頭脳"として使う（応用編）

さくらのAI Engineに加えて、自分の Anthropic APIキーを登録すると、Claude をAIの"頭脳"として使えるようになります。claude.ai のサブスクリプション（月額プラン）でのログインには対応しておらず、自分のAPIキーを登録する方法のみに対応しています。

  1. Anthropic（Claude Console）でAPIキーを発行します。
  2. 認証情報の画面（⇧ ⌘ ,）を開き、「Claude（Anthropic API）」のカードにAPIキーを貼り付けて保存します（🔌 接続テストで確認できます）。

登録が済むと、画面右下に頭脳の表示（Claude／さくらのAI Engine）が現れ、クリックするだけでその場で切り替えられます。

キーの登録状況によって、頭脳の働き方が変わります。

  • 両方のキーを登録：Claudeが司令塔（考える役）になり、まとまった作業はさくらのAI Engineに任せます。頭脳を使い分けることで、スピードと費用のバランスを取ります。
  • Claudeのキーのみ登録：Claudeがファイルの読み書きやコマンド実行まで、すべて自分でこなします。
  • さくらのAI Engineのキーのみ（またはClaude頭脳をオフ）：これまでどおり、さくらのAI Engineだけで動きます。
Claudeが料金不足などで一時的に使えなくなったときは、さくらのAI Engineのキーを登録していれば「さくらのAI Engineに切り替えて続けますか？」と提案が表示されます。自動では切り替わらないので、ボタンを押すまでは今までどおり安心して使えます。
  • モデルを選べる：お使いのAPIキーで使えるモデルを起動時に自動で読み込み、その中から選べます（新しいモデルが出たときも、Koto自体を更新せずに選べます）。
  • 画像もそのまま渡せる：スクリーンショットなどを見せると、Claude自身が読み取って対応します。
  • 会話は続きから：Claudeとのやり取りは保存されるので、Kotoを再起動しても続きから話せます。
  • 料金はさくらのAI Engineとは別枠：自分のAnthropic APIキーによる従量課金です。初めて使うときに確認画面が表示され、設定画面で月ごとの利用額の目安や、使いすぎを防ぐ警告のしきい値も設定できます。

プロジェクトを作る

「新規プロジェクト（AI）」を選ぶと、作りたいものをAIに伝えるだけで土台を用意してくれます。

  • 「お店の紹介サイトを作りたい」「簡単な掲示板アプリがほしい」など、作りたいものを日本語で入力します。
  • このあとチャットで作業するAI：さくらのAI Engine と Claude のうち、APIキーを登録済みのものだけが選べます（両方登録していればどちらか選択、使うモデルも選べます）。この選択はチャットの頭脳・モデル設定にそのまま反映されます。
  • 「作成」を押すとプロジェクトがすぐに開き、実際のファイル作成はIDEのチャットに引き継がれます。モーダルで待たされることはなく、作業の様子はチャット欄でそのまま見られます。
  • 途中で気になる点があれば、チャットで「やり直して」「続けて」のように日本語で言い直せます。うまくいかなかったときも、案内ファイルを探す必要はありません。
  • APIキーが未登録のときは、最小限のローカル雛形と案内ファイルだけが作成されます（この場合はAIへの依頼は行われません）。

1AIと一緒に作る

画面のAIチャットで、作りたい内容や直したい点を日本語で頼みます。

  • 頼み方のコツ：「トップページに問い合わせフォームを追加して」のように、具体的に伝えると正確に動きます。うまくいかないときは、もう少し細かく指示しましょう。
  • AIは必要に応じてファイルの保存やコマンドの実行を行います。実行内容はターミナルに表示されます。
  • 🪄 おまかせ：確認なしでAIが作業を進めます。スピード重視のときに便利です。
  • ✋ 毎回確認：ファイル変更やコマンド実行のたびに確認を求めます。慣れないうちはこちらが安心です。

長い相談を続けるとき（🗂 まとめ）

やり取りが長くなると、AIに渡せる分量に限りが出てきます。Kotoは、古いやり取りを捨てずに、ひとつのまとめに畳んでから渡します。だから長い相談でも「さっき決めたこと」が通じます。

  • まとめができると、会話に 「🗂 ここまでの内容をまとめました」 と出ます。黙って行うことはありません。
  • 「まとめを見る」で中身を読めます。文字は選んでコピーできますし、📋 コピーでまとめ全体を持ち出せます。
  • 📄 資料として残すを押すと、プロジェクトの「素材（公開しません）」に文書として保存できます（アプリには使われず、公開もされません）。
  • 元の会話は消えません。画面にはこれまでどおり全部残っていて、AIに渡すときだけまとめを使います。
  • まとめが必要になるのはかなり長い相談のときだけです。ふだんの会話では起こりません。
  • 「そろそろ区切りたい」「話がとっちらかってきた」と思ったら、チャット上部の 【🗂 まとめる】 でご自分でもまとめられます（直近3往復はそのまま残ります）。押しても意味がないうちは、ボタン自体が出ません。
まとめは、いまお使いのモデルが作ります。別の料金がかかることはありません。

2試す（実行して確認）

画面上部の「② 試す」ボタンを押すと、作ったものを実際に動かして確認できます。

  • Webサイトはブラウザでプレビューされ、PHPやNodeのアプリは自動でローカルサーバを起動して表示します。
  • 起動したサーバは「⏹ サーバー停止」ボタンで止められます。
  • うまく動かないときは、表示された内容をAIチャットに伝えて直してもらいましょう。

3公開する

「③ 公開」ボタンから公開できます。公開先は4種類です。

  • さくらのレンタルサーバ：HTML/PHPのサイト向け。契約済みのサーバへファイルをアップロードします。
  • さくらのAppRun：アプリをコンテナとして公開します。Dockerのインストールは不要で、Kotoが公開の準備をまとめて行います（Dockerをお持ちの上級者向けの方法も選べます）。
  • HANAMII：さくらのクラウド基盤上の国産PaaS。ZIPをアップロードするだけで、Node.jsなどの常駐アプリもそのまま公開できます。環境変数の設定にも対応しています。
  • Vercel：静的サイト／フロントエンド向けの海外PaaS。IDEがファイルをアップロードして公開します。データは国外に置かれ、常駐サーバは動かせません。
初めて公開する場合は、公開モーダル内の「🔰 初めて公開する方へ（準備すること）」を開いてください。契約やSSH・レジストリの準備手順、つまずいたときのFAQを確認できます。

公開したものを一覧で確認する：メニューの「表示」→「公開したもの一覧…」を選ぶと、これまでKotoから公開したものを公開先ごとに一覧できます（「HANAMIIに公開したのはどれだったか」をすぐ確認できます）。これはKotoに残っている公開の記録で、インターネットに繋がらないときや公開先のサービスが止まっているときでも開けます。ただしいま実際に公開中かどうかは各サービスの管理画面でご確認ください（サービス側で削除しても記録は残ります）。

公開先は、画面上部のワークフローバーからあとから変更することもできます。変更すると、AIはその環境（レンタルサーバ／AppRun など）に合った形で提案・修正を行います。環境によっては作り直しが必要になることがあるので、変更後はAIに「このまま動くか確認して」と頼むと安心です。

簡易セキュリティチェック（🛡）

秘密情報の書き込みや危険な記述がないかを、AIが簡易的に確認します。押したときだけ実行されます（公開時に自動では実行されません）。

  • 使い方：「③ 公開」を開いた画面の中に【🛡 簡易セキュリティチェック】の節があります。「要確認」のときは【🛠 AIに修正させる】を押すと、チャットに移ってAIが直しに行きます。
  • サイトかアプリかは自動で見分けます。サイト（ファイルがそのまま見える）は秘密や個人情報の露出を、アプリ（サーバーでコードが動く）は訪問者の入力の悪用（危険な命令の混入・認証のない操作など）を重点的に確認します。
  • 秘密情報が入っていそうなファイル（.env など）は中身をAIへ送らず、名前だけで判定します。
  • 公開されるファイルは全部見ます。量が多いときは何回かに分けて確認します（確認できなかったファイルがあれば、結果に名前が出ます）。
  • 最後に確認した日時が残ります：画面を開き直すと「前回の確認: 8/21 20:05 ✅ 問題なし」のように出ます（残るのは日時と結果だけで、指摘の中身は残りません）。
  • していないこと：既知の脆弱性データベースとの照合、使っているライブラリの脆弱性検査、実際に攻撃を試すこと。これらは行いません。
  • AIの利用量を使います（さくらのAI Engine）。ファイルが多いプロジェクトでは、その分だけ多く使います。
チェック後、修正するかどうかを選べます（勝手には直しません）。AIによる簡易的な確認であるため、最終的にはご自身で確認してください（判定に迷いがあるときは「要確認」側に倒して表示します）。

AIの利用量を使うところ

さくらのAI Engine は使った分だけ料金がかかります。Koto の中で AI を呼ぶのは次の場面だけです。

  • AIチャット（① 作る）：メッセージを送ったとき。作業が続くあいだ、AIは何度かやり取りします
  • 画像を読む：チャットに画像を貼って送ったとき
  • 最初のあいさつ：プロジェクトを開いたとき（1回）
  • 🗂 まとめ：会話がとても長くなったとき、または【🗂 まとめる】を押したとき
  • 🛡 簡易セキュリティチェック：ボタンを押したときだけ。ファイルが多いと何回かに分かれます
  • 公開先を変えたときの確認：公開先を切り替えたとき（そのまま動くかAIに尋ねます）

これ以外の場面では AI を呼びません（②試す・③公開・🕘 履歴・ファイルの保存などは、AI を使いません）。

使いすぎを防ぐには：認証情報（⇧⌘,）でキーごとに今月の上限を決められます。上限に達すると、上のすべての場面で AI の呼び出しを止めます。いまの使用量は画面下のバーで確認できます。
なお Claudeを"頭脳"として使う場合は、さくらのAI Engine ではなく Anthropic 側の利用料がかかります（上限の設定はそちらの管理画面で行ってください）。

どのファイルが公開されるのか

サイトやアプリの中身は public フォルダの中に入っています。ここに入れたものが、そのままサーバーへ行きます。新しく作ったプロジェクトは最初からこの形です。以前から使っているプロジェクトは、開いたときに Koto が整理します（整理する直前の状態は 🕘 履歴に残るので、あとから元に戻せます）。

左のファイル一覧は、「公開されるもの」と「公開されないもの」に分かれて表示されます。ここに出ているとおりのものが公開されます（実際に公開するときとまったく同じ判断を使っています）。

  • 公開されないものには、たとえば「素材（公開しません）」フォルダが入ります。資料や、アプリでは使わない画像はここに置いてください。
  • パスワードや鍵が入るファイル（.env など）は、置いてあっても公開されません。
  • 公開の準備に使うファイル（Dockerfile や nginx.conf）も、サイトの一部ではないので公開されません。
  • 片方に何も無いときは「（いまはありません）」と出ます。見出しは必ず両方出ますので、どちらに入っているかがいつでも分かります。
  • AIに「ファイルを作って」と頼むと、public の中に作られます。AIはこのフォルダの外には書き込めません。
パスワードやAPIキーは、ファイルに書くのではなく公開先の設定画面から登録してください。さくらのAppRun・HANAMII・Vercel はいずれも対応しています。

前の状態に戻す（🕘 履歴）

「さっきの方が良かったな」と思ったら、画面上部の「🕘 履歴（前の状態に戻す）」を押してください。作業の履歴が新しい順に並びます。

  • それぞれの行にはそのときAIに頼んだ内容が表示されます。「3つ前のデザインに戻したい」ときは、3つ前の行を選んでください。
  • 「この時点に戻す」を押すと、それより後の変更をすべて取り消して、その時点の状態にまるごと戻ります（後から追加されたファイルも消えます）。
  • 戻す直前の状態も履歴に残ります。戻しすぎても、いちばん上の行からやり直せます。
  • 記録されるのはAIの変更だけでなく、自分でエディタを編集して保存したときも同じです。
  • 履歴は直近50件まで自動で保存されます。それより古いものは順に消えていきます。
この履歴はプロジェクトのフォルダの中（.sakuraide-backup）に保存されます。プロジェクトごと別の場所へコピーすれば履歴も一緒に移動します。公開するファイルには含まれません。

困ったとき

  • まずはAIチャットに聞いてみましょう。エラーメッセージをそのまま貼り付けて「これを直して」と頼むと解決できることが多いです。
  • AIの直した内容が気に入らないときは、「🕘 履歴（前の状態に戻す）」で前の状態に戻せます。
  • エラーが出たら、ターミナルの表示内容と、直前にAIに頼んだ内容を見直してみてください。
  • 公開でつまずいたら、公開モーダル内の準備ガイドとFAQを確認してください。
