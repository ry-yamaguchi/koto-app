Kotoとは

Koto は、プログラミングが初めての方でもアプリやWebサイトを作れる道具です。作りたいものを日本語で伝えるだけで、AI がコードを書き、直し、動かします。できあがったものは、さくらインターネットのサービスにそのまま公開できます。

使い方は、画面上部に並んでいる ① 作る → ② 試す → ③ 公開 の3ステップだけです。

はじめの準備（APIキーの登録）

最初に、さくらのAI Engine の APIキーを登録します。これが AI と会話するための鍵になります。

  1. さくらのAI Engine で APIキーを発行します。
  2. Koto の 「認証情報（APIキー）」 の画面を開きます（画面いちばん上のメニュー「Koto」→「認証情報（APIキー）…」、またはキーボードの ⇧ ⌘ ,）。
  3. 「さくらのAI Engine」のカードに APIキーを貼り付けて、保存します。
APIキーはお使いの Mac の中だけに保存され（暗号化されます）、AI への問い合わせにのみ使われます。
⌘ , の「設定」は別の画面です。キーを入れるのは 「認証情報（APIキー）」 のほうです。
「認証情報（APIキー）」の一覧は「まず必要／公開先ごとに必要／開発中・自動管理」の3つに分かれています（3つ目は既定で折りたたまれています）。

プロジェクトを作る

プロジェクトとは、1つのアプリや Webサイトを入れておくフォルダのことです。「新規プロジェクト（AI）」を選び、作りたいものを伝えると、AI が最初のファイル一式を用意します。

  • 「お店の紹介サイトを作りたい」「簡単な掲示板アプリがほしい」など、作りたいものを日本語で入力します。
  • 作業する AI を選びます：APIキーを登録済みのもの（さくらのAI Engine ／ Claude）と、そのモデル（AI の種類。同じサービスでも何種類かあります）を、ここで指定します。
  • 「作成」を押すとプロジェクトがすぐに開きます。ファイルは、そのあとチャットの中で作られていきますので、様子はチャット欄でそのまま見られます。
  • 途中で気になる点があれば、チャットで「やり直して」「続けて」のように日本語で言い直せます。
  • APIキーをまだ登録していないときは、AI は動かず、ごく簡単なファイルだけが作られます。
プロジェクトのフォルダは、作成時に選んだ場所に作られます。中身は Finder からも見られますし、フォルダごとコピーすれば別の Mac へも移せます。

公開しているものをインポートする

すでに公開してあるサイトやアプリを、手元に取り込んで編集できるようにします。パソコンが変わった、人から引き継いだ、ほかの環境から引っ越したい——そんなときに使います。

  • 「新規プロジェクト」を開き、「公開先からインポート」を選びます。
  • 公開先（▲ Vercel ／ 📦 さくらのAppRun）を選ぶと、公開されているものの一覧が出ます。取り込みたいものを選んでください。
  • すでにこのパソコンの Koto が公開しているものには、その印が出ます（「このパソコンの『◯◯』が公開しているものです」）。同じものを2つ持つ理由はないので、編集を続けたいだけならそちらのプロジェクトを開いてください（確認の画面から開けます）。
  • 一覧の上に「使っているキー」が出ます。取り込みたいものが一覧に無いときは、別のキーで公開したものかもしれません。キーを切り替えると出てくることがあります。Vercel はその場で切り替えられます。さくらのAppRun で使うキーは、「認証情報（APIキー）」の画面の「さくらのクラウド」で切り替えてください（AppRun 専用のキーはなく、さくらのクラウドのキーで操作します）。
  • 「このあと、どうしますか？」で、次のどれかを選びます。引っ越しや引き継ぎなら「いまの公開を更新していく」、元を残して作り替え・複製するなら「別物として公開する」、決めかねるなら「まだ決めていない」です。この選びかたで、公開したときにいまのアプリを更新するか、新しく作るかが決まります。あとから変えると手間がかかるので、ここで決めてください。
  • 選ぶと「このあと起きること」が表示されます。「インポート」を押す前に必ず読んでください。何個のファイルが入るか、公開したときに何が起きるかが書いてあります。
  • 「インポート」を押すと、ファイルが順番に取り出されます。公開先には何も作らず、何も消しません（読み取るだけです）。
インポートが終わると、🕘 履歴に「公開されていたものをインポートした時点」が作られます。このあと AI に何をさせても、いつでもこの状態へ戻せます。
AI にも「これはインポートしたもので、勝手に作り直してはいけない」ことが伝わります。最初のあいさつで目的を確かめてくるので、違っていたらその場で言い直してください。
公開したときに何が起きるかは、公開先で違います。
  • Vercel：インポートのときに選んだとおりになります。「いまの公開を更新していく」ならもとのプロジェクトが置き換わり、「別物として公開する」なら新しいプロジェクトが作られて、もとはそのまま残ります。あとから変えたいときは、③公開の画面で「公開名」を書き換えてください。
  • さくらのAppRun：これも、インポートのときに選んだとおりになります。
    • 「いまの公開を更新していく」を選んだとき：いま動いているアプリを引き継ぎます。ここから公開すると、そのアプリが、このプロジェクトの内容で更新されます（アプリが作り直されるわけではありません）。公開のアドレス（URL）は変わりません。ポート・環境変数（公開先に登録した設定値）・メモリと mCPU・ヘルスチェックのパス（動いているかの確認に使う URL のパス）も、公開されていたときのまま引き継ぎます。月額も増えません（アプリの中身を置くコンテナレジストリは、いまあるものをそのまま使うためです）。
    • 「別物として公開する」「まだ決めていない」を選んだとき：公開するとアドレス（URL）が変わります。いま公開されているアドレスは古い内容のまま残るので、そのアドレスを誰かに伝えている場合は、新しいものを伝え直してください。また、いまのアプリも残るため月額220円（税込）が上乗せされます（コンテナレジストリが1つ増えるためです）。要らなくなったら、さくらのクラウドのコントロールパネルで古いほうを消してください。
    なお 秘密の値（パスワードなど）は取り戻せません（Koto からは読み取れないためです）。そのうえ「いまの公開を更新していく」を選んだときは、公開した時点で、公開先に設定されていた秘密の値も消えます（送り直せないためです）。いまの値を残したいときは「別物として公開する」を選んでください。くわしくは、「インポート」を押す前に出る「このあと起きること」で確かめられます。
引き継いだコンテナレジストリを、Koto が勝手に消すことはありません。引き継いだプロジェクトを破棄するときは、「コンテナレジストリ『（レジストリ名）』も削除する」のチェックが最初から外れています。プロジェクトごと削除するときは、そもそも消さずに残します（削除の確認画面にそう出ます）。どちらも、そこは Koto が作った場所ではないうえ、ほかのアプリの中身も入っているかもしれないからです。残しているあいだは、そのコンテナレジストリの月額220円（税込）が続きます。消してよいと分かっているときだけ、破棄のチェックを入れてください（入れるとこの220円が止まります）。プロジェクトごと削除したあとや、チェックを入れずに破棄したあとで消したくなったときは、さくらのクラウドのコントロールパネルから削除できます。

なお、GitHub とつないで公開しているものはインポートできません。その場合は元のファイルが GitHub にあるので、そちらから取ってください（そのほうが、直せる形のまま手に入ります）。

1AIと一緒に作る

画面右のAIチャットで、作りたい内容や直したい点を日本語で頼みます。

  • 頼み方のコツ：「トップページに問い合わせフォームを追加して」のように具体的に伝えると、正確に動きます。思ったとおりにならないときは、もう少し細かく伝えてください。
  • AI は必要に応じてファイルの保存やコマンドの実行を行います。何をしたかはチャットとターミナル（作業の記録が文字で流れるところ）に表示されます。
  • 🪄 おまかせ：確認なしで AI が作業を進めます。慣れてきて、速く進めたいときに向いています。
  • ✋ 毎回確認：ファイルの変更やコマンドの実行のたびに確認します。慣れないうちはこちらが安心です。

画像を見せる

  • 入力欄の 📎 ボタンから選ぶか、コピーした画像をそのまま貼り付けられます。「この画像みたいにして」「これは何？」のように使えます。
  • その画像をアプリやサイトの中で使いたいときは、画像の下の 【📁 画像を使う】 にチェックを入れてから送信してください。プロジェクトに保存され、AI が組み込みます。
  • チェックを入れなければ、画像は会話の中で見せるだけで、公開されるファイルには入りません。

自分で直すこともできます

  • 左のファイル一覧からファイルを開くと、その場で編集できます。💾 保存で保存してください（保存した内容も 🕘 履歴に記録されます）。
  • 自分で編集していて打ち間違えたときは、⟲ 元に戻す で直前の入力を取り消せます（AI がした作業を戻すときは 🕘 履歴を使います）。

2試す（実行して確認）

画面上部の「② 試す」ボタンを押すと、作ったものを実際に動かして確認できます。

  • Webサイトはブラウザで表示され、PHP や Node.js のアプリは、この Mac の中でサーバーを立ち上げて表示します（まだインターネットには公開されていません）。
  • 立ち上げたサーバーは 「⏹ サーバー停止」 ボタンで止められます。
  • うまく動かないときは、画面に出ているエラーの文章をそのままコピーして AI チャットに貼り付け、「これを直して」と頼んでください。

3公開する

「③ 公開」ボタンから、インターネットに公開できます。公開先は4種類です。このほかに「さくらのVPS」のタブがありますが、準備中で、いまは接続の確認だけができます。
③ 公開の画面は公開先ごとにタブが分かれ、その中の作業に ⑤ ⑥ ⑧ … と番号が振ってあります。この番号はタブごとに別のものなので、以下では「共用型タブの ⑧」のように書きます。

  • さくらのレンタルサーバ：HTML や PHP のサイト向け。契約済みのサーバへファイルを送ります。
  • さくらのAppRun：アプリを動かせる公開先です。むずかしい準備は要りません（Koto がまとめて行います。慣れた方は「エキスパート（自分の Dockerfile を使う）」も選べます）。アプリが書いたデータは残りません（共用型も専有型も同じです。くわしくは下の「アプリが書いたデータは残りません」の枠をご覧ください）。
    • 記録を残す・前に戻す：公開したあとの動きは、共用型タブの ⑧「ログ・メトリクス」に記録として残せます（記録用の保存場所を新しく作るときだけ、費用の同意をうかがいます）。公開して不具合が出たときは、共用型タブの ⑨「⏪ 公開したものを前のバージョンに戻す」で前の状態に戻せます（訪問者に見えるものが変わる操作なので、押す前に確認します。公開し直すと自動で最新に戻ります。→ 前の状態に戻す（🕘 履歴））。
    • 起動のしかた：既定の「最初のアクセスが遅くてもよい（既定・安い）」のままにしておくと、アクセスが無い間は止まり、料金がかかりません。
    • 共用型と専有型：ふつうは「共用型」のままで大丈夫です。自分のドメイン名で公開したいときは → さくらのAppRun 専有型（上級者向け）（上級者向け・月2万円〜）。
  • HANAMII：国産のクラウドサービス。サーバーで動き続けるアプリ（Node.js など）も公開できます。パスワードなどの設定値もここで登録できます。
  • Vercel：海外のサービスです。ページを見せるだけのサイト向けで、サーバーで動き続けるアプリは扱えません。ファイルは国外に置かれます。
    • トークンの範囲（Scope）：作るときに「Full Account」か「チーム全体」を選んでください。1つのプロジェクトに絞ると、そのプロジェクトしか公開できなくなります（Koto のプロジェクト1つにつき Vercel のプロジェクトが1つ作られるためです）。チームに絞ったときは、チームIDを空欄のままにしてください。なお Vercel 側でプロジェクトを作る操作は要りません（公開のときに Koto が作ります）。
初めて公開するときは、③ 公開の画面にある「🔰 初めて公開する方へ（準備すること）」を開いてください。契約や準備の手順と、つまずいたときのFAQがあります。

どこまで確かめるか：確かめ方は、公開したものの種類で変わります。Koto にまかせて公開した（標準のビルド方式）、ファイルをそのまま配るサイトは、いま公開した中身がちゃんと配られているかまで確かめます（版の目印を読むため）。サーバーで動き続けるアプリ（Node.js など）や「エキスパート（自分の Dockerfile を使う）」で公開したものは、目印が使えない（何を配るかはアプリしだい）ので、公開先の入口に1回だけ問い合わせて、応答があるかを確かめます。応答があったときは「✅ アプリが応答することを確認しました（中身が新しいかまでは確かめていません）」と、確かめた範囲をそのままお伝えします。

エラーが返ってきたとき：公開先が「404」「502」「504」のような、ページを開けなかったことを示す応答を返したときは、「応答することを確認しました」とは言いません（届いていても、開けるという証拠にはならないためです）。そのときは少し時間をおいて確かめ直します。

確認をとばすとき：とばすのは、ロードバランサの IP やホスト名が分からず、問い合わせる先そのものが無いときだけです。そのときは「確認をとばしました」と、とばした理由をお知らせしますので、公開先をご自身で開いて確かめてください。

アプリが書いたデータは残りません（共用型でも専有型でも変わりません）。アプリは「コンテナ」という使い捨ての入れもので動きます。公開し直したときだけでなく、あなたが何もしなくても入れ替わることがあり、そのたびに中身は公開したときの状態へ戻ります（台数を2以上にすると、コンテナごとに別のデータになります）。残したい入力は、「保存場所」（オブジェクトストレージ）やデータベースなど、コンテナの外に残る場所へ保存してください。
公開したアプリが、ファイルをどこまでさわれるか。公開したアプリは起動したあと、フォルダやファイルを自分で作れます。反対に、最初から入っているファイル（あなたが書いたプログラムそのもの）は、公開したアプリからは書き換えも削除もできません（どちらも、実際のさくらのサーバーでの確認はこれからです）。これは Koto にまかせて公開したとき（標準のビルド方式）の話です。「エキスパート（自分の Dockerfile を使う）」で公開したときは、中身の権限はあなたの Dockerfile どおりになり、Koto は手を出しません。
同梱したファイルを書き換えながら動く作りにすると、専有型では起動に失敗することがあります。書き換わるデータは、最初から入れずにアプリが起動時に作るフォルダへ置いてください。

公開したあと：画面上部のバーに公開した日時と 🌐 開く が出ます。ここから、公開されたページをそのまま確認できます。

これまで公開したものを見る：メニューの「表示」→「公開したもの一覧…」で、公開先ごとに一覧できます。さくらのAppRun 専有型のアプリも「📦 さくらのAppRun（専有型）」として、共用型とは別に並びます（並ぶのはアプリだけで、クラスタ・ロードバランサは専有型タブの⑥で扱います）。これは Koto に残っている記録なので、インターネットに繋がらないときでも開けます。ただしいま実際に公開中かどうかは、各サービスの管理画面でご確認ください（サービス側で削除しても、記録は残ります）。

公開先の変更：公開先は後から変えられます。画面上部の①②③が並んだバーの右端から選び直せます。変えると、AI はその公開先に合った形に直してくれます。公開先によっては作り直しが必要なこともあるので、変えたあとは AI に「このまま動くか確認して」と頼むと安心です。

簡易セキュリティチェック（🛡）

パスワードの書き込みや危険な書き方がないかを、AI が簡易的に確認します。ボタンを押したときだけ実行されます（公開のたびに自動では動きません）。

  • 使い方：「③ 公開」を開いた画面の中に 【🛡 簡易セキュリティチェック】 があります。「要確認」と出たときは 【🛠 AIに修正させる】 を押すと、チャットに移って AI が修正します。問題がなければ「✅ 問題なし（内訳を見る）」の1行に畳まれます（開くと詳しい内容を確認できます）。
  • サイトかアプリかは自動で見分けます。サイト（置いたファイルがそのまま見える）は見せたくないものが見えてしまわないかを、アプリ（サーバーでプログラムが動く）は訪問者の入力で危ないことができてしまわないかを、重点的に確認します。
  • パスワードが入っていそうなファイル（.env など）は中身を AI へ送らず、名前だけで判断します。
  • 公開されるファイルは、原則すべて確認します（上のとおり .env などは名前だけを見ます）。量が多いときは何回かに分けて確認します。確認できなかったファイルがあれば、結果に名前が出ます。
  • 最後に確認した日時が残ります：画面を開き直すと「前回の確認: 8/21 20:05 ✅ 問題なし」のように出ます（残るのは日時と結果だけで、指摘の中身は残りません）。
  • していないこと：既知の弱点リストとの照合、使っている部品（ライブラリ）の点検、実際に攻撃を試すこと。これらは行いません。
  • 実行するたびに、AI の利用量（さくらのAI Engine）を使います。ファイルが多いプロジェクトほど、多く使います。
チェックのあとに、直すかどうかを選べます（勝手には直しません）。AI による簡易的な確認であるため、最終的にはご自身で確認してください（迷いがあるときは「要確認」の側に倒して表示します）。

どのファイルが公開されるのか

サイトやアプリの中身は public フォルダの中に入っています。ここに入れたものが、そのままサーバーへ行きます。

左のファイル一覧は 「公開されるもの」 と 「公開されないもの」 に分かれて表示されます。ここに出ているとおりのものが公開されます（実際に公開するときと、まったく同じ判断を使っています）。片方が空のときは「（いまはありません）」と出るので、どちらに入っているかがいつでも分かります。

  • AI に「ファイルを作って」と頼むと、public の中に作られます。AI はこのフォルダの外には書き込めません。
  • パスワードや鍵が入るファイル（.env など）は、置いてあっても公開されません。
  • 公開の準備に使うファイル（Dockerfile や nginx.conf）も、サイトの一部ではないので公開されません。

公開したくない資料や画像は「素材（公開しません）」へ

  • 下書き・参考資料・アプリでは使わない画像などは、「素材（公開しません）」フォルダに入れておけば公開されません。
  • ここへは Finder から入れてください（プロジェクトのフォルダを開いて、そのまま入れるだけです）。AI はこのフォルダには触れません。
  • Koto が自動で入れることもあります（🗂 まとめの「📄 資料として残す」など）。
パスワードやAPIキーは、ファイルに書くのではなく公開先の設定画面から登録してください。さくらのAppRun・HANAMII・Vercel はいずれも対応しています。

前の状態に戻す（🕘 履歴）

「さっきの方が良かったな」と思ったら、画面上部の 「🕘 履歴（前の状態に戻す）」 を押してください。作業の履歴が新しい順に並びます。

  • それぞれの行にはそのとき AI に頼んだ内容が表示されます。「3つ前のデザインに戻したい」ときは、3つ前の行を選んでください。
  • 「この時点に戻す」を押すと、それより後の変更をすべて取り消して、その時点の状態にまるごと戻ります（後から追加されたファイルも消えます）。
  • 戻す直前の状態も履歴に残ります。戻しすぎても、いちばん上の行からやり直せます。
  • 記録されるのは AI の変更だけではありません。自分でファイルを編集して保存したときも同じように記録されます。
  • 履歴は直近50件まで自動で保存されます。それより古いものは順に消えていきます。
この履歴はプロジェクトのフォルダの中（.sakuraide-backup）に保存されます。プロジェクトごとコピーすれば履歴も一緒に移動します。公開されるファイルには含まれません。
🕘 履歴が戻すのは手元（Mac の中）のファイルです。すでに公開したものは、公開し直すまで変わりません。公開したものを前に戻したいときは、さくらのAppRun の公開画面にある 共用型タブの ⑨「⏪ 公開したものを前のバージョンに戻す」を使います。2つは互いに影響しません。公開中のページが壊れたときは、まず ⏪ で公開を前のバージョンに戻し、そのあと 🕘 か AI で手元のファイルを直して、もう一度公開すると安心です。

長い相談を続けるとき（🗂 まとめ）

やり取りが長くなると、一度に AI へ渡せる分量に限りが出てきます。Koto は、古いやり取りを捨てずに、ひとつのまとめに畳んでから渡します。長い相談でも「さっき決めたこと」が通じるのは、このためです。

  • まとめができると、会話に 「🗂 ここまでの内容をまとめました」 と出ます。黙って行うことはありません。
  • 「まとめを見る」で中身を読めます。文字は選んでコピーできますし、📋 コピー でまとめ全体を持ち出せます。
  • 📄 資料として残す を押すと、プロジェクトの「素材（公開しません）」に文書として保存できます（アプリには使われず、公開もされません）。
  • 元の会話は消えません。画面には全部残っていて、AI に渡すときだけまとめを使います。
  • まとめが必要になるのはかなり長い相談のときだけです。ふだんの会話では起こりません。
  • 「そろそろ区切りたい」と思ったら、チャット上部の 【🗂 まとめる】 でご自分でもまとめられます（直近3往復はそのまま残ります）。押しても意味がないうちは、ボタン自体が出ません。
まとめは、いま使っている AI が作ります。ふだんのチャットと同じAI の利用量を使います。別の料金はかかりません。

いつの会話かを見る

会話の中に日付の区切りが入ります（今日 / 昨日 / 8月21日（木））。日が変わったところにだけ出るので、あとから見返しても「これはいつの話だったか」がすぐ分かります。吹き出しにマウスを乗せると、その下に時刻（13:57）が出ます。

この機能より前の会話には、日時が記録されていません。記録が始まるところに「日時の記録がありません」と出るので、そこから上が「いつのものか分からない会話」です。あとから推測で日付を付けることはしていません。

AIの利用量がかかる場面

さくらのAI Engine は使った分だけ料金がかかります。Koto の中で AI を呼ぶのは、次の場面だけです。

  • AIチャット（① 作る）：メッセージを送ったとき。作業が続くあいだ、AI は何度かやり取りします
  • 画像を読む：チャットに画像を貼って送ったとき
  • 最初のあいさつ：プロジェクトを開いたとき（1回）
  • 🗂 まとめ：会話がとても長くなったとき、または【🗂 まとめる】を押したとき
  • 🛡 簡易セキュリティチェック：ボタンを押したときだけ。ファイルが多いと何回かに分かれます
  • 公開先を変えたときの確認：公開先を切り替えたとき（そのまま動くか AI に尋ねます）

これ以外の場面では AI を呼びません（② 試す・③ 公開・🕘 履歴・ファイルの保存など）。

使いすぎを防ぐには：認証情報の画面（⇧ ⌘ ,）で、APIキーごとに今月の上限を決められます。上限に達すると、ここに挙げた場面では AI を使わなくなります。いまの使用量は画面下のバーで確認できます。
なお Claude を「頭脳」として使う場合は、さくらのAI Engine ではなく Anthropic 側の利用料がかかります（上限の設定は、そちらの管理画面で行ってください）。

さくらのAppRun 専有型（上級者向け）

この節は上級者向けです。ふつうは「③ 公開する」のさくらのAppRun（共用型）で足ります。専有型が要るのは、自分のドメイン名で公開したいときです。「📦 さくらのAppRun」を選んだあとに出る「専有型（上級者向け）」のタブで公開すると、動いていなくても月2万円〜の固定費がかかり、独自ドメインも必要になります。

独自ドメインが無いと公開できません（⑧はクラスタができているときだけ出ます）。専有型のロードバランサは入力されたホスト名でアプリを振り分けるため、IP を直接ブラウザで開くと 404 page not found になります。アプリの不調ではありません。必ずホスト名の方で開いてください。

専有型でアプリを公開する（⑧）：専有型タブの ⑤ でクラスタを作ったあと、⑧ アプリを公開するで、クラスタの上にこのプロジェクトのアプリを載せて自分のドメイン名で公開します。ホスト名（例 app.example.com）を入れて「🚀 公開する」を押すと、確認画面のあと、Koto がアプリを公開できる形にまとめ、さくらへ送ってから専有型で動かします（少し時間がかかります）。
クラスタはふだんは既定のままで作れます（ポート・ノード数・Let's Encrypt のメールは「詳細設定」に畳んであります）。⑤ で作った直後に、⑥ で壊せることを確かめてください（消さない限り課金が続きます。削除にも数分かかります）。

DNS の A レコードを向ける：公開したら、画面に出るロードバランサの IPに向けてください（IP はその場でコピーできます）。ロードバランサに IP が付くまで数分かかることがあり、公開直後に IP が出なかったときは ⑧ の「🔄 IP を取り直す」で取り直せます（取れた IP は「公開中:」の下に「DNS の A レコード:」として残ります）。確かめられなかった IP は画面に出しません。公開のときに IP を確かめられなかったときは、前に出ていた IP は消えて「IP がまだ取れていません」に変わります（古い IP を今の IP として見せて、まちがった先に DNS を向けさせないためです）。⑥で破棄したときも、その IP は消えます。向けたあとは、https で開けるようになるまで待ってください（証明書は Let's Encrypt が自動で発行する仕組みです。実際に発行されるところは、まだ確認できていません。発行にかかる時間は、実際のさくらのサーバーでまだ確認できていません。発行されるまで https では開けません）。https で開けないときは、証明書が出ているかを確かめてください。さくらのコントロールパネルで、クラスタの「証明書情報」を開くと、発行された証明書の名前と日時が見られます。ここに何も無ければ、まだ出ていません。クラスタに Let's Encrypt のメールが無いときは ⑧ で入力します。

アプリが応答しているかの確認：公開が終わると、Koto はアプリが本当に応答しているかを確かめます。サーバーで動き続けるアプリ（Node.js など）でも確かめます。アプリがまだ応答していないと分かったとき（ロードバランサが「503」という、後ろに動いているアプリが1つも無いことを示す応答を返したとき）は「✅ 公開しました」とは表示せず、さくらのコントロールパネルで「アプリケーション → ランタイムログ」（アプリが出したエラーの記録）を見るようご案内します。このときはいまのコンテナの様子もお知らせします（さくらから届いた表示をそのまま出すので、英語のことがあります。1つも動いていないときは、その旨をお伝えします）。
公開先が「404」「502」「504」のような、ページを開けなかったことを示す応答を返したときも、「✅ アプリが応答することを確認しました」とは言いません（応答は届いていても、ページが開けるという証拠にはならないためです）。そのときは少し時間をおいてから Koto がもう一度確かめ直します。公開先をご自身でも開いて確かめ、変わらなければ同じくランタイムログをご確認ください。
確かめられる範囲は、公開したものの種類で変わります。ファイルをそのまま配るサイトを Koto にまかせて公開したときは、いま公開した中身が配られているかまで確かめます。サーバーで動き続けるアプリのときは応答があるかまでで、「✅ アプリが応答することを確認しました（中身が新しいかまでは確かめていません）」とお伝えします。
公開先につながらなかったとき・古い内容が返ってきたときは、「✅ 公開しました」を出したうえで、その旨を1行添えます（公開の手続き自体は通っているためです）。確認をとばすのは、ロードバランサの IP やホスト名が分からなかったときだけです。

アプリが書いたデータが残らないことは、共用型と専有型で変わりません。くわしくは「③ 公開する」にある「アプリが書いたデータは残りません」の説明をご覧ください。

詳細設定と、片づけ：mCPU・メモリ・台数・ヘルスチェックのパスは「詳細設定（ふつうは変えなくてよい）」に畳んであり、既定のままで公開できます。公開したアプリは「公開したもの一覧」からアプリだけを破棄できます。クラスタとロードバランサは専有型タブの ⑥ で、先にアプリを消してから、ロードバランサ → オートスケーリンググループ → クラスタ の順に消します。

Claudeを「頭脳」として使う（応用編）

ここは、ひととおり使えるようになってからで大丈夫です。さくらのAI Engine に加えて、自分の Anthropic APIキーを登録すると、Claude を AI の「頭脳」として使えるようになります。claude.ai の月額プランでのログインには対応しておらず、自分の APIキーを登録する方法のみに対応しています。

  1. Anthropic（Claude Console）で APIキーを発行します。
  2. 認証情報の画面（⇧ ⌘ ,）を開き、「Claude（Anthropic API）」のカードに APIキーを貼り付けて保存します（🔌 接続テストで確認できます）。

登録が済むと、画面下に頭脳の表示（Claude ／ さくらのAI Engine）が現れ、クリックするだけでその場で切り替えられます。

キーの登録状況によって、頭脳の働き方が変わります。

  • 両方のキーを登録：Claude が頭脳になって手順を考え、まとまった作業はさくらのAI Engine が行います。使い分けることで、速さと費用のバランスを取ります。
  • Claude のキーのみ登録：Claude がファイルの読み書きやコマンド実行まで、すべて自分でこなします。
  • さくらのAI Engine のキーのみ登録（または画面下の切り替えでさくらのAI Engine を選ぶ）：さくらのAI Engine だけで動きます。
  • モデルを選べる：Claude には性能や料金の違う種類（モデル）があります。お使いの APIキーで使える種類が一覧に出るので、その中から選んでください（新しい種類が出たときも、Koto を更新せずに選べます）。
  • 画像もそのまま渡せる：スクリーンショットなどを見せると、Claude 自身が読み取って対応します。
  • 会話は続きから：Claude とのやり取りは保存されるので、Koto を再起動しても続きから話せます。
  • 料金はさくらのAI Engine とは別：Claude の分は、その APIキーを発行した Anthropic のアカウントに、使った量に応じて請求されます。初めて使うときに確認画面が出ます。「設定」（⌘ ,）では、今月いくら使ったかを確認できます。
  • 使いすぎの警告：警告を出す金額（ドル）も決められます（警告が出るだけで、AI は止まりません）。
Claude が料金不足などで一時的に使えなくなったときは、さくらのAI Engine のキーを登録していれば「さくらのAI Engine に切り替えて続けますか？」と提案が出ます。自動では切り替わりませんので、ボタンを押すまではそのままです。
